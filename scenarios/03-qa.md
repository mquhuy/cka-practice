# Scenario 03: Node Maintenance - Q&A

## Questions & Answers

### Q: Why do we need `--ignore-daemonsets` for drain?
**A:** DaemonSets run on EVERY node by design:
- Deleting them = they immediately recreate (pointless)
- They MUST stay up (CNI, monitoring, etc.)
- `--ignore-daemonsets` tells drain "skip system pods"

---

### Q: What happens without `--ignore-daemonsets`?
**A:** Drain fails completely:
```
Node has:
├── web-pod (Deployment)          ← Can be evicted
├── kube-proxy (DaemonSet)         ← Cannot delete
└── kindnet (DaemonSet)            ← Cannot delete

Drain without flag:
❌ "Cannot delete DaemonSet pods"
→ Stops, doesn't even evict web-pod
```

---

### Q: What's the difference between cordon and drain?
**A:**
| Command | What it does |
|---------|--------------|
| `cordon` | Mark unschedulable (no new pods) |
| `drain` | Evict existing pods + cordon |

---

### Q: Why do DaemonSets exist?
**A:** To run ONE pod per node automatically:
- `kube-proxy` - networking on every node
- `kindnet` - CNI plugin on every node
- Monitoring agents - collect metrics from every node

They ignore `unschedulable` marks because they MUST be everywhere.

---

### Q: How drain works step by step?
**A:**
```
1. Cordons node (mark unschedulable)
2. Evicts pods one by one
3. Waits for graceful termination
4. Skips DaemonSet pods (with --ignore-daemonsets)
5. Confirms node empty (except DaemonSets)
```

---

### Q: How to verify drain worked?
**A:**
```bash
# Check pods moved
kubectl get pods -o wide

# Check node status
kubectl get nodes
# worker shows Ready,SchedulingDisabled during drain

# Check node taints
kubectl describe node worker | grep Taints
# Shows NoSchedule taint during cordon
```

---

### Q: Do I need to uncordon after maintenance?
**A:** Yes, to make node schedulable again:
```bash
kubectl uncordon <node-name>
# Removes NoSchedule taint
# New pods can schedule
```

## Key Commands
```bash
# Maintenance workflow
kubectl cordon <node>
kubectl drain <node> --ignore-daemonsets
# ... do maintenance ...
kubectl uncordon <node>

# Check status
kubectl get nodes -o wide
kubectl get pods -o wide
```
