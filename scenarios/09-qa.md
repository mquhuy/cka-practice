# Scenario 09: Scheduling (Node Affinity, Taints, Tolerations) - Q&A

## Questions & Answers

### Q: How does preferred affinity work?
**A:** Soft preference, not requirement:
```yaml
preferredDuringSchedulingIgnoredDuringExecution:
- weight: 100
  preference:
    matchExpressions:
    - key: env
      operator: In
      values: ["prod"]
```

**Scheduler scoring:**
```
Node A (env=prod):  +100 points
Node B (env=dev):    0 points
Node C (no label):   0 points

Winner: Node A (highest score)

BUT: If no prod nodes, still schedules elsewhere
```

**Key:** "Preferred" means "I'd like this but not required"

---

### Q: What's the difference between preferred and required affinity?
**A:**
| Type | Meaning | If no match |
|------|---------|-------------|
| `preferred` | Should match | Schedules elsewhere (soft) |
| `required` | Must match | Stays Pending (hard requirement) |

---

### Q: How does toleration work?
**A:** Permission to schedule on tainted node:
```
Node taint:   dedicated=prod:NoSchedule
Pod toleration: key=dicated, value=prod, effect=NoSchedule

Result: Pod CAN schedule on tainted node
```

**Without toleration:** Pod blocked by taint
**With toleration:** Pod allowed through

---

### Q: What are the toleration operator types?
**A:**
```yaml
# Match exact value
tolerations:
- key: dedicated
  operator: Equal      # Requires value match
  value: prod
  effect: NoSchedule

# Match any value
tolerations:
- key: dedicated
  operator: Exists     # Ignores value
  effect: NoSchedule

# Match all taints with effect
tolerations:
- operator: Exists
  effect: NoSchedule   # Any key, this effect
```

---

### Q: How to remove a taint?
**A:** Must match exact taint spec:
```bash
# Remove taint (minus sign at end)
kubectl taint nodes <node> key=value:effect-

# Example
kubectl taint nodes worker dedicated=prod:NoSchedule-

# View taints first
kubectl describe node worker | grep Taints
```

---

### Q: Why did my pod with affinity land on dev node?
**A:** That's CORRECT for preferred affinity!
- Preferred = "I'd like prod but not required"
- Scheduler chose dev for other reasons (resources, spread, etc.)
- If you wanted ONLY prod, use required affinity

---

### Q: What does `IgnoredDuringExecution` mean?
**A:** Tolerations/affinity ignored after pod running:
- `DuringScheduling` - Used for placement decisions
- `IgnoredDuringExecution` - Not enforced while running
- Pod won't be evicted if node labels change

---

### Q: How does taint enforcement work?
**A:**
```bash
# Tainted node
kubectl taint nodes worker dedicated=prod:NoSchedule

# Pod without toleration → BLOCKED
kubectl run test --image=nginx --overrides='{"spec":{"nodeSelector":{"env":"prod"}}}'
# Result: Pending (can't schedule on tainted node)

# Pod with toleration → ALLOWED
kubectl run test --image=nginx --overrides='
{
  "spec": {
    "tolerations": [{
      "key": "dedicated",
      "operator": "Equal",
      "value": "prod",
      "effect": "NoSchedule"
    }],
    "nodeSelector": {"env":"prod"}
  }
}'
# Result: Running on tainted node ✓
```

## Key Commands
```bash
# Labels
kubectl label node <node> key=value
kubectl label node <node> key-

# Taints
kubectl taint nodes <node> key=value:effect
kubectl taint nodes <node> key=value:effect-

# Node selector (in YAML or overrides)
nodeSelector:
  env: prod

# Affinity (in YAML)
affinity:
  nodeAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
    - weight: 100
      preference:
        matchExpressions:
        - key: env
          operator: In
          values: ["prod"]
```
