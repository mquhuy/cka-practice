# Scenario 01: Deployments - Q&A

## Questions & Answers

### Q: Does the exam grade commands or results?
**A:** Results only. Exam checks cluster state, not which commands you used. Your `./grade.sh` works the same - inspects what exists.

---

### Q: I used `kubectl edit deployment` instead of `kubectl set image`. Is that OK?
**A:** Yes, 100% OK. Both valid:
- `set image` - Faster (1 command), single field
- `edit` - Better for multiple changes

Both create revision history. Exam cares about outcome, not method.

---

### Q: How does the grader know I rolled back if current image is old version?
**A:** Checks rollout history:
```bash
kubectl rollout history deployment/web
# REVISION  CHANGE-CAUSE
# 1         <none>           # Initial (nginx:1.27)
# 2         <none>           # Updated (nginx:1.28)
# 3         <none>           # Rollback (nginx:1.27)

# 3 revisions = update happened + rollback happened
```

---

### Q: Why did I get 6/6 when I had a targetPort issue?
**A:** Grader gave partial credit. NodePort was correct (30080) but targetPort should be 80 (nginx's port) not 30080. Works but not best practice.

---

### Q: What does `--dry-run=client` do?
**A:** Generates YAML without creating anything:
```bash
# Without - prints success message
kubectl run foo --image=nginx

# With dry-run - prints YAML
kubectl run foo --image=nginx --dry-run=client -o yaml
```

---

### Q: Why `--dry-run=client` not just `--dry-run`?
**A:** Must specify where validation happens:
- `--dry-run=client` - kubectl validates locally (fast, default)
- `--dry-run=server` - API server validates (slower, rare need)

---

### Q: How to save output to file?
**A:** Several options:
```bash
# Redirect output
k get pods -A > output.txt

# Save with timestamps
k get pods -A | tee -a history.txt

# Select + save (iTerm2)
# Select text → Right-click → Save as...
```

## Key Commands
```bash
# Update image
kubectl set image deployment/web nginx=nginx:1.28

# Rollback
kubectl rollout undo deployment/web

# Check history
kubectl rollout history deployment/web

# Wait for rollout
kubectl rollout status deployment/web
```
